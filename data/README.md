# Data directory

Competition data is deliberately excluded from Git. Before using either method,
sign in to Kaggle and accept the Store Sales competition rules.

## Option 1: Kaggle token

Set `KAGGLE_API_TOKEN` in the environment before starting Jupyter, or enter the
token in the notebook's hidden prompt. This works in local Jupyter, VS Code, and
Colab. A token entered at the prompt is held only for the download, is never printed, and is removed from the process afterward.

## Option 2: manually downloaded ZIP

Download `store-sales-time-series-forecasting.zip` from the
[competition Data page](https://www.kaggle.com/competitions/store-sales-time-series-forecasting/data).
For local execution, place it here:

```text
data/store-sales-time-series-forecasting.zip
```

The notebooks look for the ZIP under `data/` first and then in the repository
root. The archive is extracted into `data/raw/`, and only the seven expected
CSVs are accepted.

## Extracted layout

Both methods produce the same directory:

```text
data/raw/
├── holidays_events.csv
├── oil.csv
├── sample_submission.csv
├── stores.csv
├── test.csv
├── train.csv
└── transactions.csv
```

The pipeline validates filenames, columns, keys, dates, the 16-day test horizon,
and store-family coverage before writing artifacts.

The ZIP, extracted CSVs, and generated artifacts are covered by `.gitignore` and
must not be committed.

## Resolution order

When `data/raw/` is incomplete, a notebook uses an existing
`KAGGLE_API_TOKEN`, then searches for the local ZIP. If neither exists, it asks
for a token using hidden input. Leaving that prompt empty raises an error listing
the accepted paths; it does not silently download from another source.

`data/synthetic/` is generated by `make smoke`. It imitates only the CSV schema
and key relationships. It contains no competition observations and must not be
used for model comparison or reported results.
